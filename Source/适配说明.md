# 当前版本适配

已验证 Steam build `25953419` / `release_1.0.6000.0` 与“崆峒神威”热更新 build `25957922` / `release_1.0.6000.2`，运行环境为 Unity `2020.3.49f1`、Windows x64 Mono。当前剧情角色通过协程和 Addressables 按需加载表情，创建角色后只遍历一次图片不能覆盖后续资源。

## 立绘加载

插件用 Harmony 包装 `StoryCharacterController.LoadPortrait` 和 `LoadPortraitAssetByAddressable` 返回的协程，在原加载完成后执行替换；同步 `LoadPortraitSync` 通过 Postfix 处理。同时更新 Portraits 与游戏创建的 UI Image，原 Addressables 资源生命周期交给游戏管理。

新图生成 FullRect Sprite，保留原 pivot 与等效 pixels-per-unit。`portrait-layout.tsv` 记录原画布与人物边界。加载时按 alpha>16 检测新图边界，并预留 2 像素边缘，等比缩放到对应布局，避免 PNG 留白差异造成位置漂移；纹理和 Sprite 缓存避免每次对白重复读取。

范围限于主角成人常规资料。未提供的造型沿用原图；非主角不替换。`portrait-map.txt` 可用 `角色名/原sprite名=文件名.png` 设定专属映射，通用表情可直接用原 sprite 名。

## 独立面板

属性面板 `PlayerAvatarPanel.OnEnable` 有两个 normal 分支，两者使用新常态图。人物关系面板 `SocialStatPanel.UpdateInfo` 和角色介绍 `CharacterIntroPanel.TransitionAvatar` 也有针对主角的钩子；NPC 保持原逻辑。

## 实际验证与边界

两个已支持构建均在实际游戏进程中独立创建 `StoryCharacterController`，调用真实 Setup、同步/异步加载、Addressables 与游戏 UI Image。50 个成人资源全部加载，47 个新图替换，back 与两张 shadow 保留原作；缓存、UI 引用及非主角保护通过。实际 `PlayerAvatarPanel.OnEnable` 两个天赋分支也通过。新构建证据见[验证目录](../verification/runtime-build25957922/README.md)。

测试不推进剧情或读写存档。它证明加载与显示链路可用，不代表通关所有剧情，也没有逐一操作人物关系与角色介绍界面的完整交互。原构建另经普通无测试参数的 Steam 启动确认插件加载和窗口响应；新构建本轮运行证据来自显式启用诊断的实际游戏进程。

通过 Steam 启动游戏；游戏自带的 Steam 检查可能在直接运行 Mortal.exe 时请求重新启动。插件没有绕过此检查。普通模式没有退出游戏逻辑，自测退出只在显式传入两个诊断参数时执行。

## 游戏更新

安装器的 `SupportedGameBuilds` 保存已验证构建的完整指纹组，逐组核对 Assembly-CSharp、Mortal.Core、Mortal.Story 和 Fungus 四个程序集 SHA-256，不将各 DLL 的可接受哈希拆成独立列表。`MatchedBuildId` 表示实际命中的完整指纹组；Steam 清单中的 build 仅作诊断。未知组合仍拒绝。

build `25957922` 的 Mortal.Core 指纹为 `E2FE344EA90DED6E11F06711DE86F27290E005D817B21755149F9EE24966FC9F`，其余三个受检 DLL 与旧构建相同。相关立绘接口、实现与字段经比较保持兼容，并已重新运行实际资源诊断。未对中间 build `25956595` 作实测或放行。

新增适配需重新检查方法签名、加载时序和布局，并实际运行诊断，不能仅移除版本检查。插件本身不会阻止 Steam 更新；已有 v1.0.0 安装在载荷未变时可由 v1.0.1 直接重新检查，其他载荷变化仍须按提示卸载或重新适配。
