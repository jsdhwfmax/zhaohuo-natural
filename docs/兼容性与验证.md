# 兼容性与验证

## 已验证的环境

| 项目 | 版本 |
| --- | --- |
| 平台 | Windows x64、Steam 版 |
| 游戏 | 《活侠传》，App ID `1859910` |
| Steam build 与游戏版本 | `25953419` / `release_1.0.6000.0`；`25957922` / `release_1.0.6000.2` |
| Unity | `2020.3.49f1` |
| BepInEx | `6.0.0-be.692` |
| UnityDoorstop | `4.3.0` x64 |
| 当前发行包 | `1.0.2` |
| 立绘插件 | `1.0.0` |

上述版本是本次验证依据。不能由此推断未来游戏版本、其他平台或所有 BepInEx 6 版本都兼容。BepInEx 5、IL2CPP 环境不受支持；已有 BepInEx 6 也须通过安装器对核心文件与配置的检查。

v1.0.1 新增已验证的“崆峒神威”热更新 build `25957922`，保留 `25953419`；这两次实机结果在 v1.0.2 中继续保留。v1.0.2 将结果分为两类：

- **匹配已验证构建指纹（`VerifiedFingerprint`）：**Steam 清单中的 build 和四个程序集的完整 SHA-256 组同时匹配同一已实机验证构建。
- **通过离线兼容检查（`OfflineCompatibilityProbe`）：**新 build、缺少 Steam 清单或完整程序集指纹未命中时，读取本地游戏文件进行静态检查。即使四个 DLL 没变，只要 build 未匹配，也要检查资源。通过不等于该构建已做实机或全路线测试。

没有对中间 build `25956595` 作实际游戏验证；它不会被标为已实机验证构建。版本名称相同或单个哈希符合都不能代替完整检查。不要通过删除检查代码、替换游戏程序集或混装加载器来跳过提示。

## 离线检查范围与限制

游戏更新后，先退出游戏，再从保留在游戏目录之外的 v1.0.2 完整包运行 `Install.cmd`，选择“仅检查”。工具和基线已随包提供，不需要联网或另外安装检查依赖。它由安装器触发，不会在普通游戏启动时执行。

检查主要支持**游戏资源包、运行库保持不变，立绘依赖逻辑未变且符合其余基线条件的部分代码热修复**。当前基线范围如下：

| 检查对象 | 范围 |
| --- | --- |
| 固定游戏文件 | 395 个，约 2.30 GB：130 个 Managed 依赖、190 个完整 Addressables bundles、2 个 catalog/settings、51 个场景或序列化资源、20 个 Mono 运行库或配置、`Mortal.exe` 与 `UnityPlayer.dll` |
| 全局游戏数据 | `globalgamemanagers` 只规范化唯一可见 release 版本文本，其他内容保持一致 |
| 立绘依赖实现 | `Mortal.Core` 中 147 个相关方法，包含协程状态机与传递调用的辅助方法 |
| 类型与接口引用 | 35 个类型布局，以及插件使用的 19 个游戏成员引用 |

这不是只比较 47 张图片：剧情或资源包更新也可能被保守拒绝，需要等待新版基线。首次遇到未知构建时会完整读取并校验资源，可能比已验证构建的快速检查更久，请等候结果。检查文件缺失、解析出错、关键实现或资源变化、证据不足时均不放行。

如果扫描期间 Steam 清单或受检程序集变化，检查会停止，请等更新结束后重试。工具不执行游戏程序集，不修改游戏文件，也不自动下载或生成修复补丁。通过检查只表示满足当前基线的保守条件，不保证所有未来小更新、全部剧情或其他模组组合正常。

## 实际验证内容

两个构建均通过 Steam 启动实际游戏进程，在隔离的内存对象和独立 UI 夹具中调用游戏自身的角色与资源加载链路。验证没有推进剧情，也没有读写玩家存档。下表列出的资源与显示检查在两个构建中均通过。

| 检查 | 结果 |
| --- | --- |
| 成人目录资源加载 | 50/50 通过 |
| 新立绘替换 | 47/47 通过 |
| 保留原作资源 | `back`、`shadow_left`、`shadow_right` |
| 角色正常 Setup 加载路径 | 通过 |
| 同步与异步立绘加载 | 通过 |
| 游戏 UI 的 Sprite 引用 | 通过 |
| 重复加载缓存 | 通过 |
| 非主角保护 | 通过 |
| 属性面板两个常态分支 | 2/2 通过 |
| 47 张 PNG 解码、透明度与分辨率 | 通过 |

属性面板验证调用实际 `PlayerAvatarPanel.OnEnable`；立绘验证使用实际角色控制器与 Addressables，并检查游戏创建的 UI Image 引用。

可公开复核的精简结果包括[新构建 25957922 的验证 PASS](../verification/runtime-build25957922/PASS.txt)、[原构建 25953419 的验证 PASS](../verification/runtime/PASS.txt)和[47 张 PNG 的完整性记录](../verification/art-integrity.json)。新构建的方法与字段兼容信息见[兼容检查记录](../verification/runtime-build25957922/compatibility.json)。原始个人日志不随仓库提供。

两个构建另分别进行了不带诊断参数的普通 Steam 启动检查，确认插件加载和窗口响应。原构建该次启动最后由测试用户手动关闭；新构建启动后连续观察约 81 秒，窗口响应正常，日志显示游戏与插件完成初始化。

上面的公开 PASS 文件记录资源诊断；普通启动确认另有本地记录，不公开个人日志或进程信息。普通启动检查没有覆盖完整剧情或全部界面交互。

安装器在 PowerShell `5.1.26100.9711` 中完成 **74 项集成回归检查，全部通过**，用时 188.37 秒。测试使用独立模拟游戏目录与模拟的探针返回值，覆盖以下安装器行为：

- 已验证 Steam build 与完整程序集指纹同时匹配时走快速检查；新 build 或缺少清单时调用探针，即使四个 DLL 未变。
- 正确处理探针通过、拒绝、缺失、异常、格式错误与证据不足；不把离线通过写为已实机验证构建。
- 检测期间程序集或 Steam 清单发生变化时拒绝，原本缺失的清单在检查中出现也会拒绝。
- 保留已有安装的直接检查、误解压接管、备份卸载、文件保护和失败回滚等原有路径。

逐项结果见[v1.0.2 安装器集成回归](../verification/installer-tests.json)。这 74 项验证安装器集成流程，探针本身另作下面的独立检查。

真实 Mono.Cecil 解析与资源校验在 PowerShell `5.1.26100.9711` 中通过 **12 项专项检查**，见[离线探针测试结果](../verification/compatibility-probe-tests.json)：

- 当前实际游戏只读扫描通过，本次耗时 10.38 秒；耗时随电脑与磁盘而变化。
- 在独立副本中，旧版真实 Core 配合当前已验证资源通过；无关方法实现变化、增加方法及元数据重写的组合也通过。
- 立绘直接钩子、传递资源加载辅助方法、字段布局、立绘 bundle、catalog、Addressables 运行库发生变化时均拒绝；基线或包内 Mono.Cecil 被改动时也拒绝。
- 检查结束后确认源游戏的四个程序集指纹未变。

这些结果验证静态检查的允许与拒绝边界，不表示已对未来游戏构建进行实机测试。下方 55 项保留为 v1.0.1 历史记录。

## 这些结果不代表什么

这不是全剧情、全分支或全路线通关测试。人物关系与角色介绍界面的钩子已实现，但这些界面的完整交互流程未逐一操作验证。也没有穷举与其他第三方模组共同运行的组合。

安装器不会阻止 Steam 更新游戏。旧插件文件仍在目录中，不代表更新后的游戏已通过兼容检查；升级后应先用保留的完整包重新检查。出现异常时可以卸载恢复，再查看新版发布说明。

## 自行检查

日常游玩从 Steam 正常启动即可，不需要额外参数。遇到问题时可先在安装器中进行检查，并参考[常见问题](常见问题.md)。

用于复核资源链路的独立验证参数为：

```text
--zhaohuo-portrait-selftest --zhaohuo-selftest-exit
```

这组参数会运行验证并退出，**不能用于日常游玩**。如将它们临时加入 Steam 启动选项，验证结束后请删除。验证文件位于游戏目录中的 `BepInEx/plugins/ZhaoHuoNatural/Diagnostics/`，包括逐项结果和渲染预览。请勿把个人目录或完整日志未经检查地公开上传。
