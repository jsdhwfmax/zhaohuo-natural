# 当前版本适配

v2.1.0 扩展至七角色、十三套自定义外观。400 张图片完整性与来源绑定、配置解析、身份策略、静态接口及离线兼容检查通过；实际安装升级和新 DLL 游戏验收另有独立证据。本机实测游戏为 Steam build `25957922`、`release_1.0.6000.2`，不据此保证所有未来版本兼容。

v2.1 新 DLL 完成三次真实资源诊断，覆盖代表性赵活修仙小师弟、六位 NPC（含唐布衣女版与精修版）以及七角色全部原版，并单独观察普通 Steam 启动至少 90 秒。其余五套赵活未在本次新 DLL 下逐套重跑；旧 312 张图片保持原字节，历史结果只作为未改美术的证据。未加载剧情或存档，不代表全路线通关。

## 加载与定位

插件用 Harmony 包装 `StoryCharacterController.LoadPortrait` 和 `LoadPortraitAssetByAddressable` 返回的协程，在原加载完成后替换；同步 `LoadPortraitSync` 由 Postfix 处理。同时更新 Portraits 和游戏 UI Image，原 Addressables 资源生命周期交给游戏管理。

新图生成 FullRect Sprite，保留原 pivot 与等效 pixels-per-unit。`portrait-layout.tsv` 记录原画布与人物边界。运行时按 alpha>16 检测新图边界，预留 2 像素，等比映射到对应布局，避免留白差异造成位置漂移。纹理和 Sprite 缓存避免对白反复读取文件。

替换同时要求精确游戏 Id、对象名、实际 Addressables canonical 路径，以及加载 handle 对应的 Sprite 实例。同步 hook 在 Prefix 快照原 handles，Postfix 检查新来源；协程在迭代开始和结束采用相同判定。缓存命中无新增 handle 时保留既有替换；并发或来源歧义时保留原画。

## 身份与资源边界

`CharacterPolicy.cs` 固定七个管理器角色与已核验游戏身份的映射。游戏身份不是用户配置项。基础成人资源与确证复用同一资源的成人别名才允许替换；幼年、魂及其他独立身份不因表情同名而放行。虞小梅幼年即使复用部分资源，也不纳入成人替换；龙湘已核验的成人隐藏身份可以使用本套图片。赵活旧有少年 normal 因确证复用成人资源，仍保持既有覆盖。

赵活仍用原 `Portraits`、映射和布局。NPC 分别用 `Characters/<stable-id>/Portraits` 和各自布局，没有跨角色查找。师兄女版只改变活动 PNG，不改变脚本中的称呼、性别、关系或数值。

## 配置与安装状态

运行配置 `characters.json` 使用严格纯托管解析器。SchemaVersion 2 必须完整包含七个角色，每个角色恰好一次、Enabled 为布尔值；SchemaVersion 1 仅兼容完整的旧三角色列表，新角色默认关闭。混合格式、缺项、重复、未知项、错误类型或无效 JSON 会整份禁用全部替换并记录错误。只有文件完全缺失才沿用 legacy player-only。

安装记录继续使用 Schema 4，RuntimeProtocol 从 1 升至 2。管理器先校验旧三角色配置、受管文件与记录，再将 DLL、完整新配置及选定外观作为同一事务更新。保持首次备份和原有选择，记录实际来源的三角色状态与目标七角色状态。失败与中断恢复有独立回归，未经核验的私人安装记录不自动升级。

属性面板 `PlayerAvatarPanel.OnEnable` 的两个 normal 分支继续使用赵活新图。关系面板和角色介绍的既有主角钩子保持原范围；本次未扩展 NPC 社交小头像。

## 实际验证的定义

真实诊断在 Steam 启动的游戏进程中创建独立组件，调用实际 Setup、同步/异步加载、Addressables 和 UI Image，核对每张替换、原画回退、成人别名、身份负例、批量加载与缓存。截图另做人工审阅。它不推进剧情或读写存档，也不能代表全剧情通关。

普通无诊断参数启动单独观察，不把诊断主动退出当作普通启动测试。通过 Steam 启动；直接运行 Mortal.exe 可能被游戏自带 Steam 检查重新启动。插件没有绕过该检查，正常运行没有自动退出逻辑。

## 游戏更新与离线检查

已验证快路径要求 Steam build 与四个程序集的完整 SHA-256 组同时匹配，四个文件为 Assembly-CSharp、Mortal.Core、Mortal.Story 和 Fungus。不会将各文件的可接受哈希拆开任意组合。成功标记为 `VerifiedFingerprint`，MatchedBuildId 是对应已验证构建。

新 build、缺清单或完整指纹组未匹配时，调用 `installer/CompatibilityProbe.ps1`。即使四个 DLL 没变，新 Steam build 也必须检查资源。通过标记为 `OfflineCompatibilityProbe`，MatchedBuildId 留空，不能声称未知构建已经实机验证。

探针用固定 Mono.Cecil 读取元数据、方法实现和依赖引用，并按固定基线核对资源与框架。不加载执行或改写游戏程序集。基线或工具缺失、哈希不符、解析失败、关键代码或资源变化均拒绝。

固定范围仍为 395 个文件，约 2.30 GB：130 个 Managed 依赖、190 个 Addressables bundles、2 个 catalog/settings、51 个场景或序列化资产、20 个 Mono 运行库或配置，以及 Mortal.exe 与 UnityPlayer.dll。globalgamemanagers 仅规范化唯一可见的 release 文本，其余字节须一致。代码依赖覆盖 147 个方法、35 个类型布局和当前插件的 23 个游戏成员引用。新角色资源包本已包含在固定全集中，未缩减校验范围。

v2.1 的 20 项离线兼容回归增加四个新角色资源包变异拒绝用例；配置解析、身份策略和静态接口检查另行记录。这些离线证据均不能代替新 DLL 的游戏内验收。

策略主要允许相关实现、资源和运行库未变的部分代码热修复。剧情或资源更新可能被保守拒绝；新基线必须重新核实签名、时序、资源和布局，并做对应运行验证，不能只移除版本保护。完整管理器需要由用户主动运行“仅检查”，游戏启动时不会自动触发。
